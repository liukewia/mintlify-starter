Octop 提供了预构建的 Docker 镜像，将完整的平台——Web 界面、CLI、即时通讯通道和 Agent 运行时——打包在单个容器中。对于生产环境和多用户部署，推荐使用 Docker Compose，因为它开箱即用地处理了数据卷挂载和环境配置。您的所有数据都持久化保存在命名数据卷（或主机绑定挂载）中，因此升级永远不会影响您的对话、Agent 或凭据。

<Steps>
  <Step title="拉取并使用 Docker Compose 启动">
    在克隆仓库的根目录下，使用单个命令启动 Octop：

    ```bash
    docker compose -f docker/docker-compose.yml up -d --build
    ```

    Docker Compose 会从源代码构建镜像，将您主机的 `~/.octop` 目录挂载到容器内的 `/data/.octop`，并以分离模式（后台）启动服务器。

    如需传递自定义环境变量（API 密钥、端口覆盖等），请在运行命令前创建 `docker/.env` 文件：

    ```bash
    cp .env.example docker/.env
    # 编辑 docker/.env 填入您的配置，然后：
    docker compose -f docker/docker-compose.yml up -d --build
    ```

    <Tip>
      在 `docker/.env` 中设置 `OCTOP_DATA` 可以为所有持久化数据指定自定义主机目录。这样，您只需复制单个目录即可轻松备份或迁移整个 Octop 实例。
    </Tip>
  </Step>
  <Step title="或使用独立的 docker run 启动">
    如果您不想使用 Compose，可以手动构建镜像并直接运行容器：

    ```bash
    # 从源代码构建镜像
    bash docker/docker_build.sh
    
    # 运行容器
    docker run -d \
      -p 8088:8088 \
      -v octop-data:/data/.octop \
      -e HOME=/data \
      -e OCTOP_DEFAULT_PASSWORD=changeme \
      octop:latest
    ```

    命名数据卷 `octop-data` 会在容器重启和升级期间持久化保存您的数据库、密钥和 Agent 工作区。

    <Note>
      `HOME=/data` 环境变量是必需的，这样 `~/.octop` 在容器内部才能解析为挂载了命名数据卷的 `/data/.octop` 路径。
    </Note>
  </Step>
  <Step title="打开 Web 界面并登录">
    容器启动后，打开浏览器访问：

    ```text
    http://localhost:8088
    ```

    使用首次运行时的默认凭据登录：

    | 字段 | 默认值 |
    | --- | --- |
    | 用户名 | `admin` |
    | 密码 | `octop` |

    <Warning>
      默认密码是公开已知的。请在首次登录后立即通过Web 界面中的 **设置 → 安全** 进行修改。对于无人值守部署，请在容器**首次启动之前**通过 `OCTOP_DEFAULT_PASSWORD` 环境变量设置一个强密码——凭据仅在 `~/.octop/octop.db` 尚不存在时写入一次。
    </Warning>

    如需在登录前验证容器是否健康，请运行：

    ```bash
    curl http://localhost:8088/api/health
    ```
  </Step>
  <Step title="配置模型提供商">
    Octop 支持 OpenAI 兼容 API、DashScope（通义千问）、Ollama 及其他预设提供商。您可以直接从Web 界面添加您的第一个提供商：

    ```text
    设置 → 提供商 → 添加提供商
    ```

    选择一个提供商预设，输入您的 API 密钥并保存。您也可以将常用的 API 密钥作为环境变量传递，以便它们在首次启动时立即对 Agent 运行时可用：

    ```bash
    docker run -d \
      -p 8088:8088 \
      -v octop-data:/data/.octop \
      -e HOME=/data \
      -e OCTOP_DEFAULT_PASSWORD=changeme \
      -e OPENAI_API_KEY=sk-... \
      octop:latest
    ```

    配置好提供商后，打开Web 界面中的 **对话** 部分，开始您的第一次对话。
  </Step>
</Steps>

## 环境变量

使用这些变量来配置 Octop 的 Docker 部署。对于 Docker Compose，请将它们添加到 `docker/.env` 文件中。对于 `docker run`，请使用 `-e KEY=value` 传递。

| 变量 | 默认值 | 描述 |
| --- | --- | --- |
| `OCTOP_PORT` | `8088` | 容器内部 HTTP 监听端口 |
| `OCTOP_DEFAULT_PASSWORD` | `octop` | 首次运行时的管理员密码——仅在数据库尚不存在时生效 |
| `OCTOP_ADMIN_USERNAME` | `admin` | 首次运行时的管理员用户名——仅在数据库尚不存在时生效 |
| `OCTOP_DATA` | `~/.octop` | Compose 绑定挂载的主机目录（映射到容器内的 `/data/.octop`） |
| `HOME` | `/data` | 必须为 `/data`，以便 `~/.octop` 解析到挂载的数据卷路径 |
| `OPENAI_API_KEY` | — | OpenAI 兼容 API 密钥，提供给 Agent 运行时使用 |
| `DASHSCOPE_API_KEY` | — | 阿里云 DashScope（通义千问）API 密钥 |

<Warning>
  `OCTOP_DEFAULT_PASSWORD` 和 `OCTOP_ADMIN_USERNAME` 仅在**首次启动**新的空数据卷时生效，即 `octop.db` 不存在时。数据库初始化后更改这些变量将不会有任何效果。如需在已有安装中更改管理员密码，请使用Web 界面中的 **设置 → 安全** 进行修改。
</Warning>

## 常用操作

```bash
# 跟踪容器日志
docker logs -f octop

# 在运行中的容器内执行 CLI 命令
docker exec -it octop octop --version

# 停止 Compose 栈
docker compose -f docker/docker-compose.yml down

# 在代码更新后重新构建并重启
docker compose -f docker/docker-compose.yml up -d --build
```
