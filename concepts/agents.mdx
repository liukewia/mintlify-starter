Agents are the core unit in Octop. Each user can create and run multiple agents simultaneously, and every agent operates in complete isolation — its own workspace directory, its own LLM provider settings, its own enabled skills, and its own conversation history. This lets you maintain, for example, a focused coding assistant alongside a general-purpose research assistant, without either one bleeding context into the other.

## Agent attributes

When you create an agent, you configure the following attributes:

| Attribute | Description |
|---|---|
| **Name** | A short identifier used in the UI, CLI, and channel routing |
| **Persona (MBTI)** | An optional personality profile that shapes the agent's communication style |
| **Default model** | The LLM provider and model the agent uses (e.g. `openai:gpt-4o`) |
| **System prompt** | Free-form instructions appended on top of the persona backbone in `SOUL.md` |
| **Workspace backend** | Where the agent's files are stored — local disk, COS, S3, or another remote store |

<Note>
  Each agent maintains its own conversation history, channel connections, and cron jobs. Switching between agents in the web UI or CLI does not mix their histories or settings.
</Note>

## Create an agent

Open the web UI at `http://127.0.0.1:8088` and go to **Agents**. The page has three tabs — **My agents**, **Built-in experts**, and **Expert market** — and a **Create from built-in expert** button that seeds a new agent from a template.

<Frame>
  ![Agents](/images/ui-agents.png "Agents")
</Frame>

`octop init` creates a default `main` agent so you can start chatting immediately.

<Tip>
  For CLI create, list, start, stop, and reload commands, see [Agent commands](/cli/agent-commands).
</Tip>

## Agent lifecycle

Each agent card shows its runtime state and carries a toggle to start and stop it, plus a reload control for picking up configuration changes.

| State | Meaning |
|---|---|
| **Running** | The agent is loaded and handling requests |
| **Stopped** | The agent is disabled and will not answer messages |
| **Error** | The agent hit a startup or runtime failure; check logs for details |

<Warning>
  Stopping an agent terminates its active sessions on all connected channels. Any in-progress message will not receive a reply. Restart the agent to resume.
</Warning>

## Per-agent configuration

Skills, sub-agents, personas, memory, and channels are all configured per agent under **Personalization**. Pick the agent at the top of the page, then switch between the tabs:

| Tab | What it configures |
|---|---|
| **Skills** | Installed, built-in, and marketplace skills, plus skill packages |
| **Sub-agents** | Helper agents this agent can delegate to |
| **MBTI** | The persona that shapes tone and reasoning style |
| **Memory** | What the agent retains across conversations |
| **Channels** | Messaging platforms routed to this agent |

## Expert library

Octop ships a bundled **expert library** — pre-configured agent templates for coding, research, writing, and more. Experts are templates, not running agents. Instantiating an expert creates a new, independent agent seeded with that template's configuration.

Browse them under **Agents → Built-in experts** and **Agents → Expert market**, or see [Experts & Personas](/concepts/experts-personas).

<Tip>
  Experts are a great starting point when you want a task-specialist agent. Pick the closest template, instantiate it, and then fine-tune the system prompt and skills rather than building from scratch.
</Tip>
