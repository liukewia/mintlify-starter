Channels connect your Octop agents to external messaging platforms. Once a channel is configured, every message sent to that platform is routed through Octop's IM bridge and delivered to the agent the channel belongs to. A single agent can have multiple channels active at the same time — the same agent can respond on both Feishu and Telegram, sharing one conversation context.

## Supported channels

Octop ships nine channels:

| Channel | What it connects |
|---|---|
| **WeChat** | Personal WeChat, receiving and replying to direct and group messages through an iLink Bot |
| **QQ** | A QQ bot for direct and group messages |
| **WeCom** | A WeCom bot for app messages, direct chats, and group chats |
| **Feishu** | A Feishu bot for direct and group messages, synced both ways with the agent |
| **Yuanbao** | Tencent Yuanbao, bringing agent capabilities into Yuanbao conversations |
| **DingTalk** | A DingTalk bot for direct and group chats, suited to team workspaces |
| **Telegram** | A Telegram bot for direct and group messages via the Bot API |
| **Xiaoyi** | Huawei Xiaoyi (OpenClaw), connected over the A2A protocol to the voice assistant |
| **MQTT** | Routes IoT device or robot messages to an agent |

<Note>
  The web UI is always available for chat, so you can talk to any agent immediately after creating it without configuring a channel.
</Note>

## Add a channel to an agent

Channels are configured per agent under personalization:

```text
Personalization → Channels
```

Pick the agent at the top of the page, toggle on the platform you want, and fill in that platform's credentials.

<Tip>
  For platform-by-platform credential steps, see [IM Channels](/guides/im-channels). For CLI setup, see [Channel & cron commands](/cli/channel-cron-commands#octop-channel).
</Tip>

## How message routing works

Each channel is attached to exactly one agent. When a user sends a message on the connected platform, Octop's IM bridge normalises it into a standard format and delivers it to the agent for processing. The agent's reply travels back through the same bridge to the originating platform.

```
User on Feishu
    │
    ▼
Octop IM bridge  (normalises platform message)
    │
    ▼
Agent            (processes the message)
    │
    ▼
Octop IM bridge  (sends reply back to Feishu)
    │
    ▼
User on Feishu
```

<Warning>
  Disabling a channel stops routing immediately. Any in-flight messages on that platform will not receive a reply. Re-enabling it restores routing without losing conversation history.
</Warning>
