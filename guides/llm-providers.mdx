Octop supports a wide range of LLM backends out of the box — including OpenAI-compatible APIs, DashScope (Alibaba Cloud Qwen models), Ollama for local self-hosted inference, and any custom OpenAI-compatible endpoint. You can configure providers at the agent level for fine-grained control, or set a global default that all agents fall back to. Admins manage providers through either the web dashboard or the CLI.

## Supported providers

<CardGroup cols={2}>
  <Card title="OpenAI" icon="bolt">
    Use the official OpenAI API or any drop-in compatible service. Provide a base URL and API key.
  </Card>
  <Card title="DashScope (Qwen)" icon="cloud">
    Alibaba Cloud's DashScope service hosts the Qwen family of models. Configure with your DashScope API key.
  </Card>
  <Card title="Ollama" icon="server">
    Run models locally with Ollama. Octop connects to your running Ollama instance over HTTP — no external API key required.
  </Card>
  <Card title="Custom OpenAI-compatible" icon="plug">
    Any API that follows the OpenAI chat completions spec works. Point Octop at your custom base URL and supply the appropriate key.
  </Card>
</CardGroup>

## Add a provider via the dashboard

<Steps>
  <Step title="Open Provider Settings">
    Navigate to **Settings → Providers** in the Octop dashboard.
  </Step>
  <Step title="Click Add Provider">
    Select **Add Provider** to open the provider creation form.
  </Step>
  <Step title="Choose a preset or enter a custom base URL">
    Pick a built-in preset (OpenAI, DashScope, Ollama, etc.) from the dropdown, or select **Custom** and enter the full base URL for your OpenAI-compatible API endpoint.
  </Step>
  <Step title="Enter your API key">
    Type your API key into the **API Key** field. For Ollama, leave this field blank — no key is required.
  </Step>
  <Step title="Test the connection">
    Click **Test** to verify that Octop can reach the provider and authenticate successfully. A green status indicator confirms the connection.
  </Step>
  <Step title="Save the provider">
    Click **Save**. The provider is now available to assign to agents or set as the global default.
  </Step>
</Steps>

## Add a provider via the CLI

Use the `octop models` command group for a fast, terminal-based setup.

<CodeGroup>
  ```bash Interactive wizard
  # Launch the interactive wizard to create a provider and set the active model
  octop models config
  ```

  ```bash List providers
  # Show all configured providers
  octop provider list
  ```

  ```bash Create manually
  # Create a provider without the wizard (follow the prompts)
  octop provider create
  ```
</CodeGroup>

## Set the active model

The **active model** is the global default used whenever an agent doesn't have a provider explicitly assigned.

```bash
# View or set the global active model
octop models active
```

Running `octop models active` without arguments prints the current global default. Pass a model identifier to update it.

## Use Ollama for local models

Ollama lets you run open-source models entirely on your own machine. Octop connects to Ollama over a local HTTP port — no API key or internet access needed.

<Steps>
  <Step title="Start Ollama">
    Run Ollama as a separate process on the same machine before starting Octop:

    ```bash
    ollama serve
    ```
  </Step>
  <Step title="Add Ollama as a provider">
    In the dashboard or via CLI, add a new provider and set the base URL to:

    ```
    http://localhost:11434
    ```

    Leave the API key blank.
  </Step>
  <Step title="List your local models">
    Confirm which models Ollama has available:

    ```bash
    octop models ollama-list
    ```
  </Step>
  <Step title="Pull a model if needed">
    Download a model from the Ollama library:

    ```bash
    octop models ollama-pull <model>
    ```

    Replace `<model>` with a model name such as `llama3`, `mistral`, or `qwen2`.
  </Step>
</Steps>

<Note>
  Ollama must be running before you start Octop, or before you send the first message to an agent that uses an Ollama provider. Restart Ollama if the connection test fails.
</Note>

<Tip>
  You can assign a different provider and model to each individual agent — for example, use a powerful cloud model for your research agent and a fast local Ollama model for your quick-reply agent. Go to **Agents → [your agent] → Settings → Provider** to override the global default for that specific agent. Agents without an explicit provider assignment automatically use the global active model.
</Tip>
