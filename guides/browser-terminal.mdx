Octop's **Workbench** puts a remote browser and an AI-assisted terminal side by side in the web UI, so you can watch and take over what an agent is doing in real time. A separate **Remote Desktop** page gives you control of the host's graphical desktop.

---

## Browser

The browser tab drives a real Chromium instance over CDP with persistent profiles, so agents can navigate, fill forms, and capture screenshots — and you can step in at any point.

### Enable the browser

The browser requires the `browser` extra. Install it using the method that matches how you installed Octop:

<CodeGroup>
```bash One-line installer (macOS / Linux)
curl -fsSL https://finnie-1258344699.cos.ap-guangzhou.myqcloud.com/octop/install.sh | bash -s -- --extras browser
```

```bash PyPI
pip install "octop[browser]"
```
</CodeGroup>

After installation, restart `octop run`, then open:

```text
Workbench → Browser
```

Click **Check** to confirm the environment is ready, then **Launch browser** to start a session. Type a URL in the address bar to browse; bookmarks and the AI assistant are available alongside.

<Frame>
  ![Workbench browser](/images/ui-workbench.png "Workbench browser")
</Frame>

### Use the browser in chat

Ask your agent to browse in plain language. For example:

- *"Go to news.ycombinator.com and give me the top 5 headlines."*
- *"Take a screenshot of https://example.com."*
- *"Fill in the sign-up form at [URL] with these details…"*

## Terminal

The terminal tab embeds a full interactive shell in the browser, labelled **Terminal AI+**. You can open several tabs, run commands directly, and ask the agent to suggest commands, explain output, or diagnose errors — without leaving Octop.

```text
Workbench → Terminal
```

<Frame>
  ![Workbench terminal](/images/ui-terminal.png "Workbench terminal")
</Frame>

## Remote desktop

**Remote Desktop** streams and controls the Octop host's operating system desktop. Click **Check** to verify the environment, then **Connect** to start a session; from there you can click, drag, and type directly on the remote screen.

## Guardrails

Because the browser and terminal give agents real reach into your machine, Octop centralises the safety controls under:

```text
Management → Security
```

<Frame>
  ![Security](/images/ui-security.png "Security")
</Frame>

The page is split into six tabs:

| Tab | What it controls |
|---|---|
| **Tool approval** | Tools that pause before executing and wait for you to approve or reject them in the conversation |
| **File access** | Which paths agents may read and write |
| **Sensitive information** | Redaction of secrets and personal data |
| **Command protection** | Allow and deny rules applied to shell commands |
| **Skill scanning** | Checks run against skills before they are installed |
| **Audit log** | A record of guarded actions |

Tool approval ships enabled for the highest-risk tools — `bash`, `execute`, `write_file`, and `edit_file` — but the master **Enable manual tool approval** switch is off by default. Turn it on and any tool in that list pauses for your confirmation before it runs.

Saving applies every tab at once, and running agents reload automatically afterwards.

<Warning>
  Review command protection and file access rules before giving agents shell access in a production environment. Overly permissive rules could allow an agent to run destructive commands. Start restrictive and expand only as needed.
</Warning>

<Tip>
  To enable or disable skills from the CLI, see [`octop skills`](/cli/agent-commands#octop-skills).
</Tip>
