Octop lets you schedule your agents to run prompts automatically on a cron schedule — useful for daily summaries, morning briefings, or recurring checks. A cron job fires without any manual input, so your agents can deliver results while you focus on other work.

## How cron jobs work

Every cron job has three parts:

- **Trigger** — when the job fires (a cron expression, an interval, or a one-time timestamp)
- **Prompt** — the message sent to the agent (up to 2,000 characters)
- **Task type** — `Agent` has the LLM process the prompt and generate a response; `Text` pushes the prompt directly as a plain message without LLM involvement

## Create a cron job

### Via the dashboard

<Steps>
  <Step title="Open the Cron section">
    Go to **Dashboard → Cron**.
  </Step>
  <Step title="Start a new job">
    Click **New Job**.
  </Step>
  <Step title="Set the trigger">
    Enter a cron expression (for example, `0 9 * * *` for 9 AM daily) or use an interval shorthand such as `interval:30` for every 30 minutes.
  </Step>
  <Step title="Write the prompt">
    Type your prompt in the prompt field. The limit is 2,000 characters.
  </Step>
  <Step title="Choose the task type">
    Select **Agent** to have the LLM process the prompt and generate a reply, or **Text** to send the prompt directly as a message.
  </Step>
  <Step title="Save">
    Click **Save**. The job is now active and will fire on the next matching trigger.
  </Step>
</Steps>

### Via the CLI

<CodeGroup>
```bash Create a cron job
octop cron create \
  --agent main \
  --trigger '0 9 * * *' \
  --prompt 'Give me a morning briefing on current tech news' \
  --task-type agent
```
</CodeGroup>

## Trigger formats

Octop supports three trigger formats:

| Format | Example | Description |
|--------|---------|-------------|
| Cron expression | `0 9 * * *` | Standard 5-field cron — fires at 9 AM every day |
| Interval | `interval:30` | Fires every 30 minutes from the moment the job is saved |
| One-time | `date:2025-01-15T09:00:00` | ISO 8601 timestamp — fires once at the specified time |

## Manage cron jobs with the CLI

<CodeGroup>
```bash List jobs for an agent
octop cron list --agent <id>
```

```bash Delete a job
octop cron delete --agent <id> <job_id>
```

```bash Trigger a job immediately
octop cron run-now --agent <id> <job_id>
```
</CodeGroup>

<Note>
  `octop cron run-now` requires a live Octop server (`octop run`) to be running — it dispatches the job through the running process. The `list` and `delete` commands work offline against the local database.
</Note>

<Tip>
  Set the `OCTOP_DEFAULT_TIMEZONE` environment variable or add a `"default_timezone"` key to your `config.json` to control which timezone Octop uses when evaluating cron expressions. Without this, the server's system timezone is used.
</Tip>
